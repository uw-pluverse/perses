# Java Reduction Benchmarks

A suite of real-world Java program-reduction subjects. Each subject is a
multi-file Java program that triggers a known bug in a Java compiler or a
type-based static analyzer, together with an *interestingness test* that
detects whether the bug still reproduces. They are used to evaluate program
reducers (e.g. Perses, HDD, and the cross-file `//astra` transformations) on
realistic, type-rich Java input.

The benchmarks are adapted from the paper:

> Loi Ngo Duc Nguyen, Tahiatul Islam, Theron Wang, Sam Lenz, and Martin Kellogg. 2025. Static Program
> Reduction via Type-Directed Slicing. Proc. ACM Softw. Eng. 2, ISSTA, Article ISSTA091 (July 2025), 23 pages.
> https://doi.org/10.1145/3728968

## Categories

| Prefix             | Tool under test                              | Count | Bug surfaces as |
| ------------------ | -------------------------------------------- | ----- | --------------- |
| `checkerframework-*` | [Checker Framework](https://checkerframework.org/) pluggable type checkers | 13 | a checker crash or a specific type-checking error |
| `nullaway-*`         | [NullAway](https://github.com/uber/NullAway) (Error Prone plugin), built via Gradle | 8 | a specific `[NullAway] ...` diagnostic |
| `javac-*`            | the `javac` compiler itself                  | 2 | a specific compiler error / crash |

Each subject directory is named `<tool>-<issue>` where `<issue>` is the
upstream bug/issue identifier the program was minimized from (e.g.
`checkerframework-3020` ⇒ Checker Framework issue #3020).

## Layout of a subject

Every subject is self-contained and follows the same convention:

```
<subject>/
├── info.properties     # machine-readable description of the subject
├── r.sh                # the interestingness test (exit 0 == bug reproduces)
├── <source tree>       # the .java files (and build files for NullAway)
└── output.txt          # last captured tool output (regenerated by r.sh)
```

### `info.properties`

```properties
source_file=com/google/common/util/concurrent/FuturesGetChecked.java
script_file=r.sh
required_env=[CHECKER_3_0_1=../lib/checkerframework-3.0.1]
```

| Key            | Meaning                                                                 |
| -------------- | ---------------------------------------------------------------------- |
| `source_file`  | the primary file to reduce, relative to the subject directory.         |
| `script_file`  | the interestingness test, always `r.sh`.                              |
| `required_env` | environment variables the test needs, with the value used in this repo. |

A subject may contain many more `.java` files than just `source_file` — those
are the surrounding dependencies needed to compile and reproduce the bug, and
are the targets of cross-file reduction.

### `r.sh` — the interestingness test

`r.sh` compiles/checks the program and `grep`s the output for the signature of
the bug. It exits `0` ("Found pattern.") only when the bug still reproduces, so
a reducer can use it directly as its oracle. Each script first checks that its
`required_env` variables are set and bails out otherwise. For example,
`checkerframework-3020/r.sh` runs the Checker Framework nullness checker under
the bundled JDK 8 and looks for the `ClassCastException` signature in the crash
stack.

## Setup

The subjects depend on external toolchains that are kept out of git (large
binaries) and installed on demand. Source the setup script once per shell:

```shell
source benchmark/benchmark-java/setup_env_for_sourcing.sh
```

This exports every `CHECKER_*`, `JDK*_DIR`, and `GRADLE_DIR` variable the
subjects reference, adds the `binaries/` launchers to `PATH`, and validates that
each required payload is present — automatically running the matching installer
(`benchmark/install_*.sh`) for any that is missing:

- **Checker Framework** distributions (`install_checkers.sh <version>`),
  installed under `lib/checkerframework-<version>/`.
- **JDK 8 / 17 / 21** (`install_jdk8.sh`, `install_jdk17.sh`,
  `install_jdk21.sh`), under `benchmark/binaries/jdk*`.
- **Gradle** (`install_gradle.sh`), under `benchmark/binaries/gradle`, used to
  build the NullAway subjects.

### Toolchain requirements per category

| Category           | Needs                                                            |
| ------------------ | --------------------------------------------------------------- |
| `checkerframework-*` | the matching `CHECKER_*` distribution + `JDK8_DIR` (Checker 3.x rejects newer JDKs for the spawned `javac`) |
| `nullaway-*`         | `GRADLE_DIR` + `JDK21_DIR` (NullAway runs as an Error Prone plugin and needs a modern JDK) |
| `javac-*`            | `JDK17_DIR` or `JDK8_DIR`, depending on the subject              |

The exact variables for a given subject are listed in its `required_env`.

## Running a subject

After sourcing the setup script:

```shell
cd benchmark/benchmark-java/checkerframework-3020
./r.sh
echo $?        # 0 => bug reproduces; 1 => it does not
```

To confirm that all subjects still reproduce their bugs on a freshly set-up
machine, run each subject's `r.sh` and check that it prints `Found pattern.`
